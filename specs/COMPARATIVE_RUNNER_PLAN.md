# Comparative evaluation of recorded executions

Use the existing frozen manifest and an explicitly supplied trusted export of runner executions. The export identifies the manifest and split digests, exact fixture source digest, candidate/base revisions, method, equal budget, ordered mandatory and optional checks, trusted collector execution IDs and measured per-check elapsed time. Export provenance is an operator trust assertion, not a cryptographic attestation; do not treat untrusted files as trusted. Verify canonical manifest/split digests, source binding, mandatory inventory, unique execution IDs, per-check and total budgets and status/result combinations. Require three methods and matching revisions per fixture. Missing methods, unsupported tools or absent recordings remain unavailable, never passing. Count detections, severe misses, false alarms and costs per method/language from completed results; preserve clean/defective denominators and mark incomplete comparisons. The report cannot prove independent labeling, check adequacy, ordering correctness, or runner authenticity; state those limitations explicitly.

Verification: `python3 -m unittest discover -s specs/experiments/tests -p test_evaluation.py`. CLI `python3 specs/experiments/evaluate.py --manifest MANIFEST --records RECORDS --split held-out --methods graph-only uncertainty-only combined --require-executions --report REPORT` exits nonzero on missing or unavailable required evidence and still writes an honest report when inputs exist.
